# To tickets

Use only after the implementation plan is approved. Without explicit authorization for Linear writes, return a preview.

1. Extract decisions, invariants, exclusions, acceptance criteria, and unresolved questions.
2. Resolve the Linear team and project with read tools; do not guess an ambiguous destination.
3. Split work into one outcome and one verification loop per ticket.
4. Put contracts and tests before implementation; live integrations and publication after local evidence.
5. Include context, value, in/out of scope, dependencies, acceptance criteria, validation, docs, and security notes.
6. Preview titles, placement, relationships, and assignments before writing.
7. Search for exact matches before creation so retries do not duplicate issues.
8. Stop on partial failure and report created, reused, and failed items.

An implementer must be able to complete each ticket without rereading the planning conversation.
